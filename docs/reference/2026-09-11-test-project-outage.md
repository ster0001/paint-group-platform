# 11 September 2026 — the test project ran out of IO

**What happened.** The C1 test Supabase project (`qarfyjrzgdeoqbnbbxfp`, then a `t4g.nano`) exhausted its disk-IO budget and went Unhealthy: compute at 98%, the gateway cycling, `POST /auth/v1/signup` and `/auth/v1/token` timing out (504, then nothing at 60 s) while `/auth/v1/health` and PostgREST still answered. Every customer-journey spec begins with an anonymous sign-in, so none could start, and CI on `main` was red for three merges before anyone noticed — the workflow-level concurrency group was keyed on `github.ref`, so seven branches' e2e runs hit the one project at once. The trigger was the load; the reason the load mattered was months of test data nothing ever removed: on 12 Sep the project held 10,986 anonymous users, 257 `pg.e2e.*` logins, 68,512 estimates, 40,110 invoices and 29,903 accounts in 610 MB. Anonymous users are created by the app itself (`lib/wizard/session.ts`, and the marketing chat widget in `app/(marketing)/_components/SiteChat.tsx`), so the suite never saw them as its own.

**Production was untouched, and that was proved.** 33 estimates, zero auth errors, and no `pg.e2e.*` or `@example.com` rows on the production project (`llmrvgdequpmzzuaxdhq`); the 552 `@example.com` drafts reported earlier that day were on the TEST project (`docs/briefs/estimator-v2-parking-lot.md`, "e2e-guard"). **What changed.** 11 Sep: the eight CI secret fallbacks were removed and the three `E2E_*` secrets created in their own right; the three guards read `PRODUCTION_SUPABASE_REF` and refuse without it; e2e runs one at a time behind a constant concurrency group and only on pull requests, main or dispatch; the project was moved from Nano to Micro compute (that alone restored it — it was NOT recreated). 12 Sep (C7c): a global teardown removes what each run created, a daily sweep removes what a cancelled run left, and a tripwire logs the run-created user counts at the start of every run and fails the job above 20,000. The four standing rules are in `CLAUDE.md` (Security and Process); the tooling is `scripts/c1/hygiene.mjs`.
